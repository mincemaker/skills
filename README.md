# skills

コーディングエージェント向けのスキル集。いまは OAuth / OIDC の実装を監査する `oauth-audit` だけを置いている。

## 使う前に

このリポジトリのスキルと道具は、自分が管理するシステムか、管理者から監査の許可を得たシステムを、防御のために確かめるためのものである。

- 監査は、対象のソースを手元に取得し、手元で動かすテストの中で行う。稼働中のサービスや本物の IdP に、確認のための要求を送ることは前提にしていない。
- 他人が管理するシステムに、管理者の許可なく確認のための要求を送らない。認証を求めるシステムに、照合の不備などを突いて入ることは、不正アクセス行為の禁止等に関する法律 (不正アクセス禁止法) の不正アクセス行為に当たりうる。許可の範囲を超えた要求も同じ。
- 総当たりの試験のように、相手のサービスの動作を妨げうる要求を、稼働中のサービスに送らない。刑法の電子計算機損壊等業務妨害罪に当たりうる。
- 監査テストと偽の IdP (`oauth-audit/tools/fakeidp`) は、利用者が自分の手元で、自分の意図どおりに実行するためのもの。他人の電子計算機で、その人の意図に反する動作をさせるためのプログラムではない。テストや道具を、そうした動作をするように作り変えたり、他人に実行させる目的で配ったりしない。刑法の不正指令電磁的記録に関する罪 (いわゆるウイルス作成罪) に当たりうる。
- 監査で見つけた不備は、直るまで公開しない。対象の開発元に知らせるときは、開発元が案内する脆弱性の報告の窓口を使う。日本では、IPA と JPCERT/CC が受け付ける脆弱性関連情報の届出の制度もある。公開の issue、PR、コメントに、直っていない不備の詳細を書かない。スキルも、対象のリポジトリに何も書き込まないように作ってある。
- 日本の外のシステムや利用者に関わるときは、その国の法律にも従う。

ここに書いたのは利用の目安で、法的な助言ではない。どこまでが許されるかは、対象との契約、許可の内容、個々の状況で変わる。迷ったら、監査を始める前に対象の管理者と範囲を文書で取り決め、必要なら専門家に相談する。

このリポジトリのスキルと道具は、現状のまま提供する。使った結果について、作者は責任を負わない。監査の報告は、確かめた範囲で項目を満たすかを示すもので、対象の安全を保証しない。

## oauth-audit

OAuth / OIDC の実装を、[oauth-redirect-attacks](https://github.com/mincemaker/oauth-redirect-attacks) のチェックリストで監査するスキル。IdP や認可サーバは AS-01〜AS-11、SSO やソーシャルログインのライブラリなどクライアント側は RP-01〜RP-16 で確かめる。エージェントが対象の言語で監査テストを書いて実行し、判定の報告をまとめる。

### 何をするか

1. 対象のコミットを固定し、認可サーバ (AS) とクライアント (RP) のどちらの役割を持つかを決める。
2. 対象のテスト基盤で監査テストを書く。RP の監査では、手元で動く偽の IdP に外向きの通信をすべて向ける。
3. テストを流し、項目ごとに判定する。
4. 報告を書き、道具で機械的に検査する。

判定は、その項目が守りたいものを破る攻撃が、対象で実際に成り立つかで決める。報告では次の4つを分けて出す。

| 区分 | 中身 |
|---|---|
| 脆弱性 | 攻撃が成り立つもの。テストで再現するか、決め手の1歩を示す |
| info | 攻撃は示せないが、RFC にはっきり反しているもの。RFC の原文を引く |
| 残るリスク | 対象の外の条件、例えば登録の仕方しだいで攻撃が成り立つもの |
| 所見 | そのどれでもないが、読み手に伝えておくもの |

チェックリストに無い種類の不備は見落とすことがある。報告の「確認していない範囲」に、確かめていないことを書く。

### ファイル

| パス | 中身 |
|---|---|
| `oauth-audit/SKILL.md` | 手順と判定の出し方 |
| `oauth-audit/checklist-as.md`、`checklist-rp.md` | 項目ごとの守りたいもの、攻撃の出典、テストのケース |
| `oauth-audit/report-template.md` | 報告の雛形 |
| `oauth-audit/tools/fakeidp` | RP の監査で使う偽の IdP。既定で `127.0.0.1` だけで待ち受ける |
| `oauth-audit/tools/auditcheck` | 報告とテストの機械的な検査 |
| `oauth-audit/sources/` | 判定の根拠にする原文 |
| `oauth-audit/scripts/` | 原文の取得と引用の道具 |

### 入れ方

[APM](https://github.com/microsoft/apm) で入れる。`apm.yml` の依存に、このリポジトリの `oauth-audit` を書く。

```yaml
dependencies:
  apm:
    - mincemaker/skills/oauth-audit
```

```sh
apm install
```

道具は Go 1.24 以上で動く。原文の取得と引用には Node.js を使う。

### 原文

`oauth-audit/sources/` には RFC 6749、7636、8252、9207、9700、10017 のテキストを置いている。[oauth-redirect-attacks](https://github.com/mincemaker/oauth-redirect-attacks) の `b001ca6` から写したもの。

Hideki Ikeda 氏の [攻撃手法から学ぶ OAuth セキュリティベストプラクティス](https://zenn.dev/hidebike712/books/oauth-attacks-and-bcp) と OpenID Connect Core 1.0 は、転載できないのでこのリポジトリに入れていない。使う人が次のコマンドで手元に取得する。

```sh
node oauth-audit/scripts/fetch-sources.mjs
```
